# AI INTEGRATION PORT / AI GATEWAY
## Conector universal de inteligencia artificial para todos los sistemas EOS

Todo sistema creado o adoptado bajo EOS debe disponer de un **punto estándar de integración de IA**, aunque inicialmente no utilice inteligencia artificial.

Este componente no debe obligar a instalar modelos, consumir APIs ni reservar RAM permanentemente.

Su función es dejar preparada una interfaz desacoplada que permita incorporar, sustituir o retirar proveedores de IA sin modificar la lógica principal de la aplicación.

---

## 1. PRINCIPIO

```text
APPLICATION
     │
     ▼
AI INTEGRATION PORT
     │
     ├── LOCAL MODEL
     ├── CLOUD API
     ├── PRIVATE SERVER
     ├── GPU REMOTE
     └── AI DISABLED
```

La aplicación nunca debe llamar directamente a OpenAI, Anthropic, Google, Ollama u otro proveedor desde la lógica de negocio.

Debe comunicarse únicamente con:

```text
AI Gateway
```

o:

```text
AI Provider Interface
```

---

## 2. OBJETIVO

Permitir:

- cambiar proveedor sin reescribir el software;
- conectar modelos locales;
- utilizar APIs externas;
- ejecutar modelos en otro equipo;
- mantener operación offline;
- aplicar límites de tokens;
- controlar RAM/VRAM;
- controlar costos;
- seleccionar automáticamente el modelo adecuado;
- disponer de fallback;
- evitar vendor lock-in;
- apagar completamente IA cuando no sea necesaria.

---

## 3. REGLA GENERAL

```text
IF AI is not required:
    AI_GATEWAY = DISABLED
    consume_RAM = 0 or minimum
    download_models = false

IF AI is required:
    evaluate task
    evaluate hardware
    evaluate privacy
    evaluate cost
    select execution mode
```

---

## 4. MODOS DE EJECUCIÓN

El gateway debe admitir:

```text
OFF
LOCAL
LOCAL_REMOTE
CLOUD_API
PRIVATE_CLOUD
HYBRID
AUTO
```

### OFF
IA desactivada.

### LOCAL
Modelo ejecutado en el mismo equipo.

### LOCAL_REMOTE
Modelo ejecutado en otra PC o servidor de la red.

### CLOUD_API
Proveedor externo mediante API.

### PRIVATE_CLOUD
Modelo alojado por la propia organización.

### HYBRID
Combinación local + nube.

### AUTO
EOS selecciona automáticamente la alternativa adecuada.

## 5. AI RESOURCE EVALUATOR

Antes de descargar o ejecutar un modelo:

```text
DETECT
├── RAM
├── free RAM
├── VRAM
├── GPU
├── CPU
├── disk
├── current load
├── operating system
└── active services
```

Después:

```text
MODEL REQUIREMENTS
        ↓
COMPARE
        ↓
SAFE?
├── YES → allow
└── NO  → smaller model / remote / API
```

## 6. POLÍTICA DE MEMORIA

Ejemplo:

```text
IF available_RAM < safe_threshold:
    do_not_load_model

IF model_would_cause_swap:
    reject_local_execution

IF GPU_available AND model_fits_VRAM:
    prefer_GPU

IF model_does_not_fit:
    evaluate_quantized_version

IF still_not_safe:
    use_remote_or_API
```

Nunca degradar significativamente la aplicación principal para mantener un modelo cargado.

## 21. MODEL SANDBOX

Los modelos locales y herramientas asociadas deben ejecutarse con permisos mínimos.

- filesystem completo;
- credenciales;
- correo;
- bases completas;
- terminal;
- navegador;
- red interna.

Usar permisos explícitos por herramienta.

## 40. PRINCIPIO FINAL

Todo sistema EOS debe poder incorporar inteligencia artificial sin quedar dependiente de una marca, proveedor o modelo concreto.

La arquitectura objetivo es:

```text
APPLICATION
    ↓
AI INTEGRATION PORT
    ↓
POLICY ENGINE
    ↓
RESOURCE EVALUATOR
    ↓
AI ROUTER
    ↓
┌──────────┬──────────┬──────────┐
│ LOCAL    │ PRIVATE  │ CLOUD    │
│ MODEL    │ SERVER   │ API      │
└──────────┴──────────┴──────────┘
```

El sistema debe poder funcionar:

```text
WITH AI
WITHOUT AI
LOCAL AI
REMOTE AI
CLOUD AI
HYBRID AI
```

sin tener que reconstruirse para cambiar entre ellos.

## Regla suprema

> La inteligencia artificial debe comportarse como una capacidad conectable y gobernada del sistema, no como una dependencia rígida incrustada en toda la aplicación.
