## Integridad y autoridad

Los archivos se copiaron byte a byte y `.gitattributes` impide normalizar sus finales de línea. `library.json` contiene sus SHA-256 y el validador compara los bytes actuales. Esto detecta diferencias respecto del manifiesto; no prueba quién escribió una conversación ni constituye firma criptográfica del propietario. Si se cambian fuente y manifiesto juntos, la revisión Git debe detectar y justificar ese cambio.

El material histórico puede contener comandos, reglas propuestas, afirmaciones de vigencia y URLs con parámetros de seguimiento. Conservarlo literalmente no convierte esos contenidos en instrucciones activas ni en información actual verificada. Para trabajo real aplica constitución, aclaraciones editoriales, permisos del host, alcance del usuario y fuente primaria pertinente.

No «corrijas» el antecedente para que parezca haber dicho algo distinto. Registra una aclaración en trazabilidad y desarrolla el control en el manual. Si un futuro adjunto contiene secretos o datos privados no necesarios, minimiza/redacta antes de publicación y registra que la copia es una versión derivada; no declares identidad byte a byte cuando hubo redacción.

## Evolución y frescura

Las listas históricas de proveedores, precios, estándares y legislación son pistas para investigar. Cada producto que tome una decisión crea su registro de fuentes con URL oficial, fecha, alcance revisado, owner y próxima evaluación. Una referencia identificada no equivale a revisión de todo el texto, anexos y modificaciones. El repositorio no mantiene un monitor automático de cambios por conservar estas URLs.

La preservación de esta edición está limitada a los cuatro textos entregados y al repositorio autorizado, cuya visibilidad privada se conserva. No habilita redistribución pública de otros materiales ni cambios a las cuentas del propietario.
